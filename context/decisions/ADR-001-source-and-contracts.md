## Decision proposal
Use NYC Open Data **311 Service Requests (2020 to Present)** dataset `erm2-nwe9`, Socrata JSON API `https://data.cityofnewyork.us/resource/erm2-nwe9.json`. Single public source satisfies source-count requirement when queried across sufficient range. Use keyset pagination over `created_date,unique_key`, persist cursor with bronze page, backfill UTC `[start,end)`, quality threshold 5%, stage then publish silver+gold atomically. SCD2 models **observed successive** `unique_key` attribute changes, not inferred historical versions.

## Must verify (Spec 01 smoke test)
- API endpoint available; dataset actually contains ≥1M usable real records in chosen span.
- Queryable stable `created_date`, `unique_key`; sort/cursor correctness; data dictionary; numeric vs string ID type; timezone.
- Rate limiting/token requirements, update behavior and possible deletion, `:updated_at` availability; decide rolling lookback for modified records.
- Tracked SCD2 fields that genuinely change on repeated pulls; if insufficient, propose stronger source-backed dimension before implementation.
- Allowed column names and privacy policy; no raw free-text in logs.

## Tradeoffs
Current-state API exports cannot reconstruct earlier status history. Dates backfill **creation dates**, not arbitrary prior versions. Full source may be large; stream pages and stage in PostgreSQL, never load all data in memory. No third-party paid account assumed; app token optional and secret by environment.

### Exact engineering policy to review

- **Retry:** one in-flight request; at most four attempts including the first; 5s connect and 30s total per-attempt timeout, with all attempts/waits inside a 180s monotonic per-page deadline. Retry DNS/transport timeout/reset, HTTP 202/408/429/500/502/503/504 and explicit stale/lagging-secondary responses. Other HTTP errors, TLS verification failure, malformed JSON/envelope, breaking type/order errors and missing/invalid mandatory freshness metadata fail without retry. A changed pinned generation fails immediately rather than retrying until a convenient view appears.
- **Backoff:** after failed attempt n, full jitter `[0,min(30,2**(n-1))]` seconds. Valid Retry-After delta-seconds/HTTP-date is a minimum wait, plus nonnegative jitter; never shorten it. If the wait plus an attempt cannot fit the remaining deadline, return a retryable exhaustion error without an early request. Invalid/negative header falls back to backoff with a sanitized metadata warning. Wall clock parses HTTP-date; monotonic clock governs deadlines. Inject clocks/jitter/sleeper in fixtures; no real waits/network in unit tests.
- **Freshness:** accept a page only with explicit false out-of-date flag, valid truth/secondary modification times, secondary not older than truth and a truth generation matching the caller's pinned generation (if supplied). First accepted page proposes the generation. Missing/invalid markers give source_freshness_unknown; true/lagging views retry within the same budget. No accepted Page or candidate next cursor is returned on failure. Header/request ID diagnostics exclude tokens/bodies. These markers are conservative proxies, not a documented snapshot token; no permissive fallback silently disables them.
- **Bounds/reconciliation (future integration, not this exception):** freeze creation `[start,end)` and update `[lower,upper)` before extraction. Proposed update upper is run start minus 5min; lower is last successfully published upper minus 48h, with explicit initial lower/cohort. Daily update extraction plus weekly full bounded-cohort creation scans use separate checkpoint segments. Count equality alone is insufficient; reconciliation compares identities/content. A generation change invalidates the run; later integration must re-extract the same frozen scope as a new audited run without advancing successful watermarks.
- **Unavailable/unreliable-source fallback:** fail visibly after retry budget; do not publish, advance durable progress or present complete synchronization. If update metadata cannot be trusted, review a full selected-cohort scan/reconciliation and its runtime/cost before enabling it. Missing rows become review candidates, not automatic deletions; full replacement is not millions of SCD2 changes. If sufficiently fresh bounded extraction remains infeasible, pause live integration and review an official dated export for backfill only or an evidence-backed alternative. Exports/fixtures do not establish live change capture. No reconciliation executor or export loader is permitted in the client-only scope.
- **Selected time interpretation:** America/New_York for offset-free source event values, explicitly provisional and not publisher-confirmed. Preserve raw/source-wall-time cursor values; update metadata is independently parsed as UTC. Future silver conversion uses IANA round-trip checks: one UTC candidate is valid, none/nonexistent or two/ambiguous candidates are quarantined with reasons, never guessed. Record tzdata policy/version. The client-only slice parses cursor kinds and preserves wall times; it does not implement silver normalization/quarantine or claim dataset timezone verification.
